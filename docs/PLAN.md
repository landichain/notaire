# Notaire SaaS: Project Plan

> Status: **draft for approval**. No code has been written yet.
> Shared version with diagrams: https://claude.ai/code/artifact/5a425ebe-f872-4fdc-81d0-2f8a681deeaa

## 1. Scope

This is a **management app for notary offices**. It is not a legal tool. It organises an office's clients, files, appointments, payments, staff and documents. Many offices use it (SaaS), and each office sees only its own data.

| Decision | Choice |
|---|---|
| Users | Notary offices in Morocco, many offices on one platform |
| Languages | French + Arabic (full right-to-left layout) |
| Platform | Web app in the browser |
| Hosting | In Morocco |
| Currency | Moroccan dirham (MAD) |

**Left out on purpose:** deed drafting, tax and fee calculators, anti-money-laundering checks, links to government services, and CDG accounting. Because the app holds no legal rules, we do not need a notaire to validate it before launch. Any of these can be added later if offices ask for them.

## 2. Users and roles

| Role | What they can do |
|---|---|
| Platform admin (us) | Creates offices, manages subscriptions, handles support. Cannot see an office's data. |
| Notaire (office owner) | Sees and edits everything in the office. Adds staff and sets their roles. |
| Clerc | Clients, files, documents, agenda. No access to payments unless the notaire allows it. |
| Secrétaire | Clients, agenda, document upload. |
| Comptable | Payments and receipts. Read-only on clients and files. |

## 3. Features (all in the first version)

1. **Clients**
   - People: name in French and Arabic, CIN or passport, phone, email, address.
   - Companies: name, RC, ICE, legal representative.
   - Search, duplicate warning, and the list of each client's files and payments.
2. **Files (dossiers)**
   - One file per case: number, type (sale, gift, company, loan…), the clients involved and their role (seller, buyer…), assigned staff member, notes.
   - Status: Open → In progress → Signed → Closed, with the date of each change.
   - The file page shows everything in one place: clients, documents, appointments, payments.
3. **Agenda**
   - Appointments and signing dates by day, week and month, for each staff member.
   - Each appointment is linked to a file and its clients.
4. **Payments**
   - Amount agreed for each file, then each payment received (cash, cheque, transfer).
   - Remaining balance per file and per client.
   - A printable PDF receipt in French or Arabic.
5. **Staff and roles**
   - The notaire invites staff by email and gives each a role.
   - A log of who changed what.
6. **Documents**
   - Upload scans, PDFs and photos to a file or a client.
   - Preview, download, and search by name and type.
7. **Dashboard**
   - Open files by status, today's and this week's appointments, unpaid balances, recent activity.

Every screen works in French and Arabic. Each user picks their language.

## 4. Data model

Every table except Office carries an `office_id`, and the database blocks one office from reading another's rows (PostgreSQL row-level security).

| Table | Holds | Linked to |
|---|---|---|
| Office | Name, address, logo, subscription | — |
| User | Name, email, password, 2FA, role, language | Office |
| Client | Person or company, IDs, contacts | Office |
| Dossier | Number, type, status, assigned user, notes | Office |
| DossierClient | A client in a file and their role | Dossier, Client |
| Appointment | Date, time, place, staff, notes | Dossier, User |
| Payment | Amount, date, method, receipt number | Dossier, Client |
| Document | File, type, size, uploaded by | Dossier or Client |
| AuditLog | Who did what, and when | Office, User |

The amount agreed for a file lives on the Dossier. The balance is that amount minus the sum of its payments.

## 5. Technical architecture

One Next.js app does both the screens and the server logic, so a single developer can build it and run it. It sits on a server rented in Morocco, with the database and file storage beside it.

| Part | Choice |
|---|---|
| App | Next.js + TypeScript, Tailwind, shadcn/ui |
| French / Arabic | next-intl, with the layout mirrored for Arabic |
| Database | PostgreSQL + Prisma, with row-level security per office |
| Login | Email + password, optional 2FA |
| File storage | MinIO (S3-compatible), encrypted |
| PDF receipts | Generated by the app |
| Email | Staff invitations, password reset |
| Hosting | Docker on servers from a Moroccan provider, with daily backups to a second site |
